SEO · AI 검색 대응 참고

01. 개요 및 적용 범위

  • 이 문서는 기존 퍼블리싱 규칙을 바탕으로 검색엔진과 AI가 문서 의미를 해석하기 쉬운 HTML 구조를 정리한다.
  • 검색 노출, 순위 또는 AI 서비스의 노출 결과를 보장하지 않는다.
  • 기존 HTML 규칙, 웹접근성, image 규칙을 우선 적용한다.

02. 문서·메타 정보

  • 페이지 주제를 알 수 있는 title을 작성하고, 템플릿 페이지도 화면별 제목을 구분한다.
  • html의 lang 값은 문서 언어와 일치하게 작성한다.
  • meta description은 화면 내용과 일치하는 문구를 기획·운영과 협의해 적용한다.
  • canonical, robots, hreflang과 서버 응답 메타 정보는 개발·운영 협의 항목이다.

03. 콘텐츠 구조와 시맨틱 마크업

  • 페이지의 주제를 나타내는 h1을 하나 두고, 이후 제목은 내용 순서에 맞게 계층을 유지한다.
  • 본문은 main, 독립 콘텐츠는 article, 주제 단위는 section, 탐색 링크는 nav처럼 의미에 맞는 요소를 사용한다.
  • 나열된 정보는 ul·ol, 행과 열 관계가 있는 정보는 table로 작성한다.
<main id="contents">
    <article>
        <h1>페이지 주제</h1>
        <section>
            <h2>세부 주제</h2>
            <p>주제를 설명하는 본문</p>
        </section>
    </article>
</main>
  • 시맨틱 태그와 제목 계층의 상세 기준은 HTML 규칙을 따른다.

04. 이미지·링크·동적 콘텐츠

  • 정보성 이미지는 내용을 설명하는 alt를 작성하고, 장식 이미지는 alt=""로 제공한다.
  • 링크 텍스트만으로 이동 목적을 알 수 있게 작성한다. ‘자세히 보기’처럼 반복되는 문구에는 주변 제목 또는 aria-label로 목적을 보완한다.
  • 검색에 필요한 핵심 제목과 본문이 JavaScript 실행 뒤에만 생성되는지 개발과 확인한다.
  • 이미지 속성, 지연 로딩, picture 사용 기준은 image 페이지를 따른다.
  • 비동기 콘텐츠의 렌더링 방식과 초기 HTML 제공 여부는 개발 협의 항목이다.

05. 구조화 데이터

  • 구조화 데이터는 화면에 실제로 표시되는 정보와 일치해야 한다.
  • 퍼블리셔는 화면의 제목, 날짜, 작성자, 가격 등 정보가 의미 있는 HTML 구조로 제공되는지 확인한다.
  • JSON-LD 작성, 데이터 생성, 타입 선택 및 검증은 개발·기획·운영 협의 후 적용한다.

06. AI 검색 대응 원칙

  • 질문에 답할 수 있도록 제목과 본문을 구체적으로 작성하고, 같은 의미의 키워드를 나열하지 않는다.
  • 보이지 않는 텍스트나 화면 내용과 다른 문구를 검색용으로 추가하지 않는다.
  • 제목, 본문, 목록, 표, 링크의 관계가 HTML 구조에 드러나게 작성한다.
AI 검색 대응은 별도 마크업을 추가하는 작업이 아니라, 기존 HTML 구조와 콘텐츠 의미를 명확히 하는 작업이다.

08. 최종 체크리스트

  • 페이지 주제와 h1, title이 서로 어긋나지 않는가?
  • 제목, 본문, 목록, 표, 링크가 의미에 맞는 HTML로 작성되었는가?
  • 정보성 이미지의 alt와 링크 목적이 화면 맥락에서 명확한가?
  • 숨김 텍스트나 검색용 키워드 나열을 사용하지 않았는가?
  • 메타 정보 출력, 초기 HTML 제공, 구조화 데이터는 개발·기획·운영과 협의한다.
